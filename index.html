Stockfish 18 in NotiChess: source code

The NotiChess mobile app includes the Stockfish chess engine, free software licensed under the GNU General Public License, version 3 (GPL v3). The engine runs as a separate program, with which the app exchanges UCI text commands. This folder holds the complete corresponding source of the engine shipped in the app, as the GPL v3 requires. The license text is in each archive (Copying.txt) and on the licenses page of the app.

What the app ships

  • Android: Stockfish 18, release sf_18 of the official project (github.com/official-stockfish/Stockfish), compiled by NotiChess from the official sources, without any modification, as libstockfish.so for arm64-v8a (ARCH=armv8) and armeabi-v7a (ARCH=armv7-neon). License: GPL v3.
  • iOS: Stockfish.js 18, release v18.0.0 of github.com/nmrugg/stockfish.js (Chess.com and Nathan Rugg, based on Stockfish): stockfish-18.js, stockfish-18.wasm, stockfish-18-single.js and stockfish-18-single.wasm, as published, without any modification. License: GPL v3.

On both platforms, the two NNUE networks below are included in the engine at compile time, and shipped inside it.

Building the Android engine

Extract stockfish/src and stockfish/scripts from stockfish-android-armv8.tar (the Makefile runs ../scripts/net.sh), and copy the two .nnue files into stockfish/src. Then, in stockfish/src, with the tools of the Android NDK used by Flutter (flutter.ndkVersion) on the PATH, for each ABI:

env -u CXXFLAGS -u LDFLAGS -u DEPENDFLAGS -u EXTRACXXFLAGS -u COMPCXX \
  make -j<N> build ARCH=<armv8|armv7-neon> COMP=ndk KERNEL=Linux \
  EXTRALDFLAGS="-static -Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384"

then llvm-strip stockfish. <N> is the number of parallel jobs, with no effect on the binary. Only compiler and linker flags differ from the official release build: the 16 KB page alignment required by Android 15 and Google Play; KERNEL=Linux, without which a macOS host adds -mdynamic-no-pic; build instead of profile-build, whose profiling step would run the Android binary on the host.

moteur.sh does all of this: placed in a scripts folder, scripts/moteur.sh android <NDK folder> checks the three Stockfish files above, compiles both ABIs and writes each libstockfish.so under android/app/src/main/jniLibs/. It downloads these files from their original sources, unless they are already in .cache/moteur/sf_18/, next to the scripts folder: put the copies from this page there, and nothing is downloaded.

Building the iOS engine

Extract stockfish.js-v18.0.0.tar.gz and copy the two .nnue files into its src folder (the build downloads them otherwise). With Node.js, make and emscripten 3.1.7 installed and on the PATH, run, in the extracted folder, ./build.js --all --only-single --only-standard (./build.js --help lists the options; without the two --only options, the other editions need networks that are not provided here). It builds, in src, stockfish-18.js and stockfish-18.wasm (multi-threaded), stockfish-18-single.js and stockfish-18-single.wasm (single-threaded), with both networks embedded in the .wasm. NotiChess ships these four files as published in the release (github.com/nmrugg/stockfish.js/releases/tag/v18.0.0), without any modification.

Compiler le moteur Android

Extraire stockfish/src et stockfish/scripts de stockfish-android-armv8.tar (le Makefile lance ../scripts/net.sh), et copier les deux fichiers .nnue dans stockfish/src. Puis, dans stockfish/src, avec les outils du NDK Android qu'utilise Flutter (flutter.ndkVersion) dans le PATH, pour chaque ABI :

env -u CXXFLAGS -u LDFLAGS -u DEPENDFLAGS -u EXTRACXXFLAGS -u COMPCXX \
  make -j<N> build ARCH=<armv8|armv7-neon> COMP=ndk KERNEL=Linux \
  EXTRALDFLAGS="-static -Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384"

puis llvm-strip stockfish. <N> est le nombre de tâches parallèles, sans effet sur le binaire. Seuls des drapeaux de compilation et d'édition de liens diffèrent de la compilation de la release officielle : l'alignement sur des pages de 16 Ko, qu'exigent Android 15 et Google Play ; KERNEL=Linux, sans quoi un hôte macOS ajoute -mdynamic-no-pic ; build au lieu de profile-build, dont l'étape de profilage exécuterait le binaire Android sur l'hôte.

moteur.sh fait tout cela : rangé dans un dossier scripts, scripts/moteur.sh android <dossier du NDK> vérifie les trois fichiers de Stockfish ci-dessus, compile les deux ABI et écrit chaque libstockfish.so sous android/app/src/main/jniLibs/. Il télécharge ces fichiers depuis leurs sources d'origine, sauf s'ils sont déjà dans .cache/moteur/sf_18/, à côté du dossier scripts : y ranger les copies de cette page, et rien n'est téléchargé.

Construire le moteur iOS

Extraire stockfish.js-v18.0.0.tar.gz et copier les deux fichiers .nnue dans son dossier src (la construction les télécharge sinon). Avec Node.js, make et emscripten 3.1.7 installés et dans le PATH, lancer, dans le dossier extrait, ./build.js --all --only-single --only-standard (./build.js --help en donne les options ; sans les deux options --only, les autres éditions demandent des réseaux qui ne sont pas fournis ici). Il construit, dans src, stockfish-18.js et stockfish-18.wasm (multi-thread), stockfish-18-single.js et stockfish-18-single.wasm (mono-thread), avec les deux réseaux embarqués dans le .wasm. NotiChess livre ces quatre fichiers tels que publiés dans la release (github.com/nmrugg/stockfish.js/releases/tag/v18.0.0), sans aucune modification.
